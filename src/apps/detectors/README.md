# Детекторы — какие правила работают по скважинам

Обзор всех правил в `apps/detectors/`. Подробности, пороги и история решений —
в README каждого правила. Состояние на 26.10.2026.

| Код | Что ловит | Фонд | Источник | Когда считается | README |
|---|---|---|---|---|---|
| R2 | обрыв / отворот штанг | ЭВН-КУДУ, СДМО Danfoss VLT (`type_1900 = 6`) | телеметрия СДМО, 15-мин корзины | по приходу данных + подметальщик каждые 15 мин | `rod_breaks/README.md` |
| R9 | перекос нагрузки (насос недоподаёт) | ШГН (`type_1900 = 1`) | телеметрия СДМО, суточно | 04:10, вчерашние сутки | `load_imbalance/README.md` |
| R10 | падение дебита по замерам ЦИТС | только ЖМГ | замеры WinCC/ЦИТС + техрежим | 06:30 за вчера, каждый час в :40 за сегодня | `cits_events/README.md` |

Все три пишут эпизоды в `detectors_incident` (warning → alarm, уровень только
растёт; закрытие по явной причине), отдаются через `GET /detectors/v1/incidents`.

## R2 — обрыв штанг (`rod_breaks/`)

- **Признак:** момент на штанге (регистр 1991) проваливается, а скорость
  ротора (1998) остаётся прежней: вал крутится без нагрузки. Сравнение с
  медианой за последние 24 ч, корзины по 15 минут.
  - **warning** — момент ниже 60 % обычного держится 1 час;
  - **alarm** — ниже 40 % держится 3 корзины подряд (~45 минут).
- **Закрытие:** момент выше 75 % базы держится 3 часа.
- **Запуск:** без расписания по часам — диспетчер ставит прогон, когда
  загрузчик СДМО привёз новые данные; `detectors.sweep` раз в 15 минут
  догоняет отставшие станции.
- **Проверка ложных тревог** (`detectors.rod_breaks.verify`, ежечасно в :30):
  каждый эпизод сверяется с ремонтами и статусами ABAI, статусом привода СДМО
  (регистр 1999), моментом и замерами нефти ЦИТС. С 19.10.2026 (PR #41)
  добавлено правило восстановления: если через 1–6 ч после срабатывания
  средний момент вернулся к 75 % обычного и выше — тревога ложная.

## R9 — перекос нагрузки (`load_imbalance/`)

- **Признак:** суточный `K = |P5| / P95` по моменту на валу — насколько
  обратные (генераторные) пики выросли относительно рабочих. Ветви:
  - `abs` — K ≥ 0.20;
  - `rel` — K ≥ 0.13 и в 1.5 раза выше собственного фона скважины (60 суток);
  - `loss` — рабочий пик P95 упал ниже 10 % фона.
- **Что значит:** утечка в клапанах, износ плунжера, неполное заполнение
  насоса, нарушено уравновешивание.
- **Уровни:** первые сутки с тревогой — warning, вторые — alarm.
- **Закрытие:** 4 чистых суток подряд (`recovered`) или 14 суток без валидных
  данных (`stale`).
- **Запуск:** раз в сутки в 04:10 за вчерашние сутки; диспетчер может
  продублировать, повтор идемпотентен.

## R10 — падение дебита по замерам ЦИТС (`cits_events/`)

- **Признак:** замеры жидкости относительно техрежима, только ЖМГ.
  - **отклонение** — Qж ≤ 70 % плана на 3 замерах подряд (warning);
  - **нулевые замеры** — 2 замера подряд ≤ 0.5 м³/сут (alarm);
  - **замер устарел** — старше 7 суток (периодическая эксплуатация — 14);
  - **пустой замер** — Qж не заполнен.
- Скважины, которым в ABAI уже поставили простой, не оцениваются.
- **Закрытие:** простой в ABAI (`idle`), замер устарел (`stale`), серия ушла
  в хронику (`chronic`), замер в норме (`recovered`).
- **Запуск:** 06:30 за вчерашние сутки (пропуски догоняет по курсору) и
  ежечасно в :40 за сегодняшние неполные сутки — только открывает и повышает
  эпизоды.

## Что строится поверх правил

| Что | Правила | Когда | Где |
|---|---|---|---|
| ИИ-заключение по эпизоду | R2, R9 | при открытии / эскалации эпизода | `conclusion/`, `GET/POST /detectors/v1/conclusions` |
| Суточная ведомость по НГДУ (docx) | R2, R9 (ведомость R10 подготовлена, выключена решением владельца) | сборка 07:30 | `services/daily_sheet/`, `GET /detectors/v1/reports/daily-sheet` |
| Рассылка ведомостей на почту | R2, R9 | 07:50 | `tasks/mail_daily_sheets/` |
| Проверка эпизодов независимыми данными | только R2 | ежечасно в :30 | `rod_breaks/verification/` |

## Как устроен запуск

- `tasks/dispatch` — диспетчер: загрузчики телеметрии после коммита зовут
  `dispatch_detectors(source, entity_ids)`, он по реестру `detectors_detector`
  (флаг `enabled`, источник, дебаунс `min_interval_sec`) ставит задачи правил.
  Новое правило = пара «код → celery-задача» в `RUNNER_TASKS`.
- `detectors.sweep` — подметальщик: раз в 15 минут сравнивает курсоры
  `detectors_cursor` с фронтом данных и допинывает отставших.
- Расписание суточных задач — `src/entrypoints/celery.py`.
- Включено ли правило на конкретном стенде — флаг `enabled` в
  `detectors_detector`, в коде не видно.
