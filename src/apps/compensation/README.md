# Контур компенсации

Недобор стоящих скважин закрывается разгоном работающих скважин-доноров.
Решения владельца — 29.09.2026; с 04.11.2026 — пул и подбор по методике
(«Методика подбора скважин-доноров», ред. 3; план `docs/donor_pool_methodology_plan.md`,
критерии теста — `docs/donor_gzu_test_criteria.md`). Объекты — Жайкмунайгаз и
Кайнармунайгаз (только VMB).

## Понятия

- **Потеря** — скважина в состоянии «стоит» или «ремонт» по таблице состояний
  (`wells_well_state`: ABAI + привод СДМО). Величина — средняя **фактическая**
  нефть по ABAI за 10 суток до остановки (жидкость × (1 − обводнённость) ×
  плотность из техрежима); нет факта — план техрежима (`loss_source = plan`);
  нет и плана — `no_plan`, в подбор не идёт. Пишется подбором в
  `compensation_loss`; эндпоинты читают оттуда.
- **Донор** — строка пула (`compensation_donor`), пересчитывается каждый день.
  Прирост = средняя нефть × ступень, целевая скорость = скорость по СДМО ×
  (1 + ступень). Ступень — по погружению (глубина насоса − Ндин): > 300 м —
  15 %, 200–300 — 10 %, 150–200 — 7 %, 100–150 — 5 %. Риск по ступени (15 % —
  низкий, 10 % — средний, меньше — высокий) — справочно.
- **Пара** — «потеря → донор» (`compensation_recommendation`), статус
  `pending` → `accepted` / `rejected` → `applied`. Открыта, пока `closed_at` пуст.

## Пул (`compensation.build_pool`, раз в сутки в 06:10)

Работающий фонд проверяется критериями методики — нужны все сразу
(`services/pool.py`): в работе; ШГН или ЭВН; ряд добычи ≥ 25 из 27 суток;
нефть ≥ 2 (ЭВН) / 2,5 (ШГН) т/сут; коэффициент вариации ≤ 0,30;
обводнённость ≤ 90 %; погружение ≥ 100 м; МРП ≥ 180 сут; исправность по
телеметрии за 72 ч (ШГН — K = |P5|/P95 момента ≤ 70-го процентиля по
месторождению; ЭВН — разброс момента ≤ 0,06, дрейф ≤ 8 %; заполнение насоса
P5 ≥ 70 % ШГН / ≥ 90 % ЭВН).

- Прошедшие с телеметрией — `in_pool = true`; без телеметрии — отдельный
  перечень (`has_telemetry = false`), в подбор не идут.
- Не прошедшие или переставшие работать доноры остаются строками с
  `in_pool = false` (на них ссылаются пары); причины — в `source_row.fails`.
- Пометки методики (после ПРС < 30 сут, наработка насоса, CV > 0,25,
  обводнённость ≥ 85 %, ряд без изменений) не исключают — `source_row.flags`,
  в `GET /donors` — `flags`.

Источники (`services/pool_data.py`): суточная нефть — ABAI (`meas_liq`,
`meas_water_cut`, техрежим); способ эксплуатации и глубина спуска — ревизия
фонда (`wells_fund_revision`), где пусто — оборудование ABAI; Ндин — более
свежее из ГДИС и ревизии; МРП — между двумя последними ПРС; телеметрия — СДМО;
ГЗУ — зеркало ГЗУ.

```bash
cd src && python -m apps.compensation.tasks.build_pool.build_pool --dry-run
```

Ревизия фонда сейчас загружена разово (`apps/wells/data/fund_revision_2026-10-28.json`,
`python -m apps.wells.tasks.load_fund_revision.load_fund_revision`); позже её
будет присылать эндпоинт.

## Подбор (`compensation.assign_donors`, раз в час в :15)

По каждому НГДУ пула:

1. Потери пересчитываются и пишутся в `compensation_loss`.
2. Пары закрываются: потеря снята (`loss_resolved`), донор встал / в аварии /
   выпал из пула (`donor_unavailable`) или у потери доноров больше лимита
   (`donor_limit`, только пары «на согласовании»).
3. Потери от больших к меньшим; доноры — только **своей ГЗУ** (вариант «а»),
   из пула, не стоящие и без аварии, не отклонённые для этой потери; потеря без
   ГЗУ доноров не получает.
4. Минимальный набор: сначала свободные доноры с большим приростом, затем
   перехват; не больше `MAX_DONORS_PER_LOSS` (3) доноров на потерю, включая
   открытые пары; донор — за одной потерей.
5. **Перехват** (с 31.10.2026, `docs/compensation_preemption_plan.md`): потеря
   забирает донора из пары «на согласовании» у потери меньше хотя бы в
   `PREEMPT_RATIO` (1,2) раза (у потери без оценки — всегда), если сама стоит
   не меньше `PREEMPT_AFTER_HOURS` (6 ч) и покрытие не падает. Жертвы — сначала
   самая мелкая потеря, у неё донор с большим приростом. Принятые и
   применённые пары не трогаются; пара владельца закрывается с
   `donor_preempted`.

```bash
cd src && python -m apps.compensation.tasks.assign_donors.assign_donors --dry-run
```

«Компенсировано» = прирост закреплённых доноров, но не больше потери.

## Эндпоинты `/compensation/v1`

| | Параметры | Что |
|---|---|---|
| `GET /contour` | `well_id` | контур стоящей скважины (`stopped` / `no_plan` / `working`) |
| `GET /recommendations` | `ngdu_id`, `oil_field_id`, `limit` | открытые пары, крупные сначала |
| `GET /donors` | `ngdu_id`, `oil_field_id`, `status` | пул (`in_pool`) со статусами, пометками и шапкой вкладок |
| `GET /losses` | `ngdu_id`, `oil_field_id` | стоящие скважины, величина и источник потери, доноры |

Согласование — `services/approval.py`, эндпоинт не публикуется до утверждения
процесса.

## Не сделано

- эндпоинт согласования; `applied` по скорости из СДМО; фактический прирост по
  замерам; `losses_compensation` в главных KPI;
- «резкое падение дебита» как событие-потеря (методика, п. 1);
- ежедневная ревизия фонда через эндпоинт;
- запас по оборотам привода и пропускная способность ГЗУ не проверяются —
  прирост сценарный.
