# Контур компенсации

Недобор стоящих скважин закрывается разгоном работающих скважин-доноров.
Решения владельца — 29.09.2026.

## Понятия

- **Потеря** — скважина в простое по ABAI (`wells_well_status`, код `DWN`) или
  в незавершённом ремонте. Величина — план Qн по техрежиму (как в сводке НГДУ,
  лаг до 31 суток); без плана — `no_plan`, в подбор не идёт.
- **Донор** — строка пула (`compensation_donor`). Прирост = Qн × ступень,
  целевая скорость = скорость × (1 + ступень). Риск по ступени: 15 % — низкий,
  10 % — средний, 5–7 % — высокий (ступень автор выбирал по погружению).
- **Пара** — «потеря → донор» (`compensation_recommendation`), статус
  `pending` → `accepted` / `rejected` → `applied`. Открыта, пока `closed_at` пуст.

## Подбор (`compensation.assign_donors`, раз в час в :15)

По каждому НГДУ пула; у Кайнармунайгаза — только VMB (и потери, и доноры).

1. Пары закрываются: потеря снята (`loss_resolved`), донор встал / в аварии
   (`donor_unavailable`) или у потери доноров больше лимита (`donor_limit`,
   только пары «на согласовании», худшие по порядку из п. 3).
2. Потери от больших к меньшим (величина — текущий план Qн); доноры — только с
   того же месторождения, работающие, без аварии, не отклонённые для этой
   потери.
3. Порядок поиска для потери: свободные низкого и среднего риска (ближние
   раньше; без координат — в конце группы) → перехват таких же → свободные
   высокого риска → перехват высокого.
4. Добираем, пока потеря не покрыта, но не больше `MAX_DONORS_PER_LOSS` (3)
   доноров на потерю, включая уже открытые пары; донор — за одной потерей.
5. **Перехват** (с 31.10.2026, `docs/compensation_preemption_plan.md`): потеря
   забирает донора из пары «на согласовании» у потери меньше хотя бы в
   `PREEMPT_RATIO` (1,2) раза (у потери без плана — всегда), если сама стоит не
   меньше `PREEMPT_AFTER_HOURS` (6 ч) и покрытие НГДУ не падает. Жертвы —
   сначала самая мелкая потеря, у неё ближайший донор. Принятые и применённые
   пары не трогаются. Пара владельца закрывается с `donor_preempted`; взятый
   донор сразу числится за новой потерей. Без перехвата потеря, вставшая
   позже, оставалась без доноров при разобранном пуле (VMB_2503 на 30.10).

Сухой прогон — что изменится, без записи:

```bash
cd src && python -m apps.compensation.tasks.assign_donors.assign_donors --dry-run
```

Лимит — замечание заказчика 27.10.2026: пул КМГ (28 доноров) меньше суммы
потерь, и крупнейшая потеря забирала его целиком — 14 доноров у одной
скважины, у остальных пусто. Общее покрытие от лимита не меняется, меняется
только то, за какими потерями закреплены доноры.

«Компенсировано» = прирост закреплённых доноров, но не больше потери.

## Эндпоинты `/compensation/v1`

| | Параметры | Что |
|---|---|---|
| `GET /contour` | `well_id` | контур стоящей скважины (`stopped` / `no_plan` / `working`) |
| `GET /recommendations` | `ngdu_id`, `oil_field_id`, `limit` | открытые пары, крупные сначала |
| `GET /donors` | `ngdu_id`, `oil_field_id`, `status` | пул со статусами и шапкой вкладок |
| `GET /losses` | `ngdu_id`, `oil_field_id` | стоящие скважины и их доноры |

Согласование — `services/approval.py`, эндпоинт не публикуется до утверждения
процесса.
